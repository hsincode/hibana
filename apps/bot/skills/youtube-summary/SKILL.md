# YouTube 字幕ダウンロード & 要約

`/skills/youtube-summary/scripts/yt-subs.py` が字幕を原語のまま取り、
タイムスタンプ付き Markdown にする。要約はそれを読んで自分で書く。

## hibana での実行（これだけやる）

スクリプトは sandbox に **マウント済み**。workspace にコピーしない。
`download_media` は動画・音声用で字幕は取れないので、ここでは `bash` を使う。

```bash
python3 /skills/youtube-summary/scripts/yt-subs.py get "<URL>" -o /workspace
```

- **`-o /workspace` を必ず付ける。** 既定の `/tmp` はコンテナ内 tmpfs で、
  `read_file` / `send_file` から見えない。
- 出力は `/workspace/<video_id>.md`。`read_file` で読む（大きい動画は
  `offset` / `limit` で分割。目安 20,000 字超なら分割して読む）。
- 60 秒動画でもメタデータ取得で 10 秒前後かかる。長尺なら `timeout_secs=120`。

## 手順

1. `bash` で上のコマンドを実行する。標準出力に採用言語・段落数・出力パスが出る。
2. `read_file` で `<video_id>.md` を読む。
3. 要約を書いて `send_message`（下のフォーマット）。文字起こし自体を求められた
   ときだけ `send_file` で `.md` を渡す。

字幕の有無が怪しいときだけ、先に `list` で確認する:

```bash
python3 /skills/youtube-summary/scripts/yt-subs.py list "<URL>"
```

## 要約のフォーマット

Discord 返信なので **2000 字以内**。長くなるなら要点を削らず節の説明を削る。

```
**<タイトル>** — <チャンネル> / <長さ>

<1〜2 文で「何の動画で結論は何か」>

**要点**
- 3〜6 個。数値・条件・順序は動画が言っている通りに書く（丸めない）
- ...

**内容**
`[00:35]` <節の要旨 1〜2 行>
`[02:54]` ...
```

- 時刻は文字起こしの `[mm:ss]` をそのまま使う。動画内を探し直せることが要約の価値。
- チャプターがあるなら **チャプターを「内容」の見出しにする**（著者が付けた区切り）。
- 自動字幕は固有名詞・専門用語を高確率で誤る。文脈で直し、確証がないものは
  断定せず「（字幕では「X」。おそらく Y）」と書く。
- 概要欄の宣伝・リンク・ハッシュタグは要約に混ぜない。動画が言っていない結論も足さない。
- 丸写しや長い引用はしない。引用は必要な 1〜2 文まで。
- 要約はユーザーの言語（通常は日本語）で書く。文字起こしが何語でも同じ。

## 詰まったとき

| 症状 | 対処 |
|------|------|
| `Sign in to confirm you're not a bot` | VPS の IP が弾かれている。`vpn_status` → 落ちていれば `vpn_connect` して再実行 |
| `言語 'xx' の字幕が無い` | 原語字幕が無い動画。`list` の結果を見せて、別言語で妥協するか聞く（`--lang xx`） |
| `動画の言語を判定できなかった` | 言語メタデータが無い古い動画。`list` の候補から `--lang` を指定 |
| 字幕が一切無い | 字幕からは要約できない。`download_media` で音声を落とす案を出して判断を仰ぐ（自動でやらない） |
| 本文が短い / 欠ける | `--interval 0` で生のキューを確認。ASR が途中で切れている動画がある |

## オプション

| オプション | 用途 |
|-----------|------|
| `--lang ja` | 言語の自動判定が外れたとき。`ja` でよい（`-orig` はスクリプトが選ぶ） |
| `--interval 30` | 段落の粒度（秒）。細かい時刻が要るなら 30、`0` でキュー単位 |
| `-o /workspace` | 出力先。hibana では必須 |
