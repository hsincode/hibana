# ADR-0005: API・Web は、本番に切り替える前に確かめる

- 状態: 採用
- 決定日・判断者: 2026-10-04、持ち主
- 判断の過程を残した Issue: #3（作り直す範囲）、#5（方式の選択。表の 2）
- 置き換える／置き換えられた ADR: なし

## 要求と決定
- プロダクトの特性と、満たす要求:
  - 配信先が API・Web・bot の 3 つあり、API を最初に出す。bot と Web は API に依存するので、壊れた API が本番に出ると全体が止まる
  - これまでの API・Web の配信は `vercel deploy --prod` だけで、起動しないビルドでも実行は成功し、そのまま本番に出た（#1 の観察 3）
  - 要求は、起動しないビルドや、意図と違うビルドが本番のドメインで配信されないこと
- 採用する構成・方式:
  1. 本番用のビルドを、ドメインを向けない状態で作る（`vercel deploy --prod --skip-domain`）
  2. そのデプロイ固有の URL に対して `scripts/verify-deployment.ts` を実行する
     - API: `/healthz` が 200 を返すこと（アプリの起動、環境変数、DB への接続、起動時の移行を通る）と、`/version` が配信中の commit を返すこと
     - Web: ページの `<meta name="hibana-commit">` が配信中の commit であることと、ページが読み込むスクリプトを取得できること
  3. 確認に通ったときだけ `vercel promote` で本番のドメインを切り替える
  - commit は配信の job が `HIBANA_COMMIT` として渡す（API は実行時の環境変数、Web はビルド時）
  - デプロイ固有の URL には Deployment Protection がかかるので、Protection Bypass for Automation の secret をヘッダーで送る
- 比較した代替案と、採用しなかった理由:
  - 配信後に確認して戻す（`vercel rollback`）: 仕組みが単純。確認が終わるまで壊れた版が本番に出る。Hobby プランでは直前の本番にしか戻せない
  - 切り替え前と切り替え後の両方で確認: ドメインを切り替えた後だけに起きる問題（OAuth のリダイレクト、CORS）も拾える。手順が最も多く、失敗する箇所も増える
  - 持ち主の言葉での理由は #5 に追記する

## 影響
- 得られる効果: 確認に通らないビルドは本番のドメインに向かない。そのとき実行は失敗し、本番は前の版のまま残る
- 費用・運用の負荷・残る制約:
  - リポジトリの Secret が 2 つ増える（`VERCEL_BYPASS_API`・`VERCEL_BYPASS_WEB`）。登録するまで、API・Web の配信は確認の段階で失敗する
  - 確認するのは起動と commit の一致まで。機能が正しく動くかは PR の検査（テストと画面テスト）に任せる
  - ドメインを切り替えた後だけに起きる問題は拾えない
  - 段階配信した API は、確認のときに起動時の移行を本番の DB に対して実行する。切り替えを取りやめても、スキーマの変更は残る。前の版の API が新しいスキーマでも動くことが前提になる（DB の変更は追加だけにする規則。別の ADR で定める）
  - bot の配信が失敗して前の版に戻っても、API・Web は戻さない（#5 の見直し）。API が 1 つ前の bot・Web と互換であることが前提になる
  - `--skip-domain` と `promote` が、いま使っている Vercel のプランで動くかは、最初の配信で確かめる
- セキュリティ・障害時の挙動:
  - `/version` は commit を返すだけで、認証をかけていない。リポジトリは public で、commit は秘密ではない
  - bypass の secret は確認の step にだけ渡す。Vercel のトークンは確認の step に渡さない
  - 確認が失敗・タイムアウトした場合は切り替えない。段階配信したデプロイは残るが、どのドメインも向かない

## 実装と検証
- 適用した commit・構成図: この ADR を追加した PR
- 要求ごとの検証記録:
  - 確認の規則: `scripts/verify-deployment.test.ts`（起動しない、別の commit、commit を返さない、スクリプトがない、保護にかかった、起動中の再試行）
  - `/version`: `apps/api/src/app.test.ts` の `version`
  - Web の meta: `HIBANA_COMMIT` を渡してビルドすると `dist/index.html` に入り、渡さないと入らない（2026-10-04 に手元で確認）
- 実際の運用・CI/CD の実行記録: マージ後に、確認を通って切り替えた最初の実行と、確認で止まった実行（訓練）を追記する

## 見直す条件
- ドメインを切り替えた後だけに起きる問題で本番が壊れたとき（切り替え後の確認と切り戻しを足す）
- 確認に通ったのに本番で機能が動かないことが続いたとき（確認する内容を増やす）
