# ADR-0009: ハーネスをプロバイダーで分け、Anthropic 公式 API だけを Claude 向けにする

- 状態: 提案（実装済み。持ち主がマージを決めた時点で「採用」に変える）
- 決定日・判断者: 構成と対象は 2026-10-11、持ち主（#66）。同日、持ち主の指示で、段階ごとの PR をやめて 1 つの変更にまとめた。出し方などの細部は AI の案のまま実装しており、本人未確認
- 判断の過程を残した Issue: #66（構成・対象・出し方の比較と、本人の判断）、#68（サブエージェント）、#69（前後の比較の計測）
- 置き換える／置き換えられた ADR: なし

## 要求と決定
- プロダクトの特性と、満たす要求:
  - bot のハーネス（システムプロンプト、モデルに見せるツール、ループ、会話の持ち方）は Codex CLI を参考に作られ、全プロバイダーで同じものを使っていた。Anthropic のターンにも、Codex 向けのプロンプト（`apps/bot/prompts/harness/codex.md`）とツール（`shell_command`、`apply_patch` など）を送っていた（#66 の「判断時点の事実」）
  - 要求は 3 つ。Anthropic のモデルに合ったハーネスにすること。Anthropic 以外のプロバイダーに送るリクエストを変えないこと（#67）。bot だけで切り戻せること（ADR-0006）
- 採用する構成・方式:
  - ハーネスを 2 つ持つ。`codex`（従来のもの。変えない）と `claude`（新しく作った）。内容は [docs/harness.md](../harness.md)
  - `claude` の対象は `provider === "anthropic"` のターンだけ。`claude_max` と `claude_kiro` を含むほかのプロバイダーは `codex` のまま（持ち主の決定）
  - `claude` は、Messages API のまま、Claude Code と同じ名前と入力の形のツール、Claude 向けに書いたプロンプト、追記だけの会話にする。Claude Agent SDK は使わない（持ち主の決定）。プロンプトの本文は Claude Code から写さず、公開文書をもとに書いて、出所を `docs/harness.md` に記録する
  - 選び方: bot の環境変数 `ANTHROPIC_HARNESS`。既定は `claude`、`codex` にすると `anthropic` も従来のハーネスで動く。API・DB・契約（`apps/api/src/contract.json`）には項目を足していない。#66 で AI が推奨した「guild の許可リストで先行する」形は作っていない。持ち主の「まとめて Claude Code 再現型の実装にする変更にして」という指示を、切り替えそのものをこの変更に含める意味に AI が読んだため（本人未確認）
  - 会話とチェックポイントのキーに、`claude` のときだけハーネスの識別子を足す。`codex` のキーは従来と同じ文字列。別のハーネスのチェックポイントは再開しない
  - 既存のループ（`Agent.run`）と会話の保存（`History`）をそのまま使い、ハーネスの違いは分岐で入れた。Anthropic が返したブロックは、従来どおり `providerBlocks` にそのまま持って送り返す
- #66 の案から変えた点（AI の判断。本人未確認）:
  - **公式 SDK（`@anthropic-ai/sdk`）への置き換えはしていない。** 送受信は従来の `fetch` の実装を直して使っている。動いている再試行と無通信の監視を置き換える利点が、この変更の中では小さいと判断した
  - **会話を送受信した内容そのままの別の表に持つ形にはしていない。** 既存の `Message` の形のまま、失敗の印（`is_error`）と結果の中の画像を項目として足した（ADR-0008 のとおり、既存の項目の意味は変えていない）。送る内容は、保存した会話から毎回同じ手順で組み立てる
  - **refusal のときのサーバー側の fallback は入れていない。** 別のモデルへの課金が出るため、判断（#66 の 6）を待つ
  - **読める版と書く版を 2 回に分けて配信していない。** 下の「障害時の挙動」のとおり、配信に失敗して前の版に戻った場合の影響は、進行中だったターンの再開に限られる
- 比較した代替案と、採用しなかった理由（#66 の比較表。理由の整理は AI によるもので、持ち主の言葉での理由は聞いていない）:
  - Claude Agent SDK を組み込む: 文字どおりの再現になる唯一の案。1 セッションが 1 子プロセスで、目安は 1 GiB RAM / 1 CPU。bot の中核の書き直しになり、#31・#44・#46・ADR-0008 で決めた制御が CLI 側に移る
  - Managed Agents: 自前のコードが最も少ない。Claude Code そのものではなく、Discord のツールと guild 単位の作業領域をイベント経由に作り替える必要がある
  - ハーネスを 1 つのまま、全プロバイダーぶんを Claude 向けに書き換える: 非推奨にする側のリクエストも変わり、比べる相手の「旧」が残らない

## 影響
- 得られる効果:
  - Anthropic のターンが、Anthropic のモデルに合わせたプロンプト・ツール・会話の持ち方で動く
  - 新旧を同じビルドで、環境変数だけを変えて比べられる（#69）
  - この変更で見つけて直した不具合（出力上限で切れた応答の再送、Edit の置換文字列、入力長の超過の判定など）は、`claude_max` を含む Anthropic 経路と、ファイルの編集ツールにも効く
- 費用・運用の負荷・残る制約:
  - 当面、2 つのハーネスを持つ。`codex` 側は `harness-freeze.test.ts` で固定している
  - 切り替えと切り戻しのたびに、`anthropic` を使うチャンネルの会話が 1 回最初からになる。この変更を配信したときにも起きる
  - 画像をデータとして保存するので、会話の保存ファイルが大きくなる（実測していない）
  - 会話の要約、サブエージェント、tool search は、それぞれ追加のリクエストや課金を生む（実測していない）。サブエージェントは回数・同時実行数・往復数で縛っており、金額の上限は無い（#68）
  - Anthropic の beta の機能（要約、thinking の表示）に依存する。拒否されたら、その機能なしで続ける
  - Claude Code の更新への追従は、自分たちの作業になる
- セキュリティ・障害時の挙動:
  - guild / DM 分離、権限チェック、Docker サンドボックスの上限は、どちらのハーネスでも同じ実装（`ToolRegistry` とサンドボックス）を通る。`claude` ではツールの一覧を会話の全員で同じにしたので、実行のときに本人の権限で判定し直している
  - 切り戻しは 3 段。VPS の `bot.env` で `ANTHROPIC_HARNESS=codex` にして再起動する。revert の PR をマージして配信する。起動に失敗したときは relay が自動で 1 つ前の commit に戻す（ADR-0006、変更なし）
  - relay が前の commit に戻した場合、前の版は `claude` のキーを知らないので、そのチャンネルの会話を捨てて最初から始める。`claude` で保存された再開用のチェックポイント（2 時間有効）は、前の版では `codex` のツールの下で再開されうる。そのターンは失敗する可能性がある（未検証）
