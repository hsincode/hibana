# ADR-0010: Anthropic 以外のプロバイダーを非推奨にし、今のハーネスのまま凍結する

- 状態: 提案（実装済み。持ち主がマージを決めた時点で「採用」に変える）
- 決定日・判断者: 非推奨にすることと「隠して凍結、削除は後日」は 2026-10-11、持ち主（#67）。凍結の定義、隠す範囲、表示の出し方は未定
- 判断の過程を残した Issue: #67（どこまで行うかの比較と、本人の判断）、#66（新しいハーネスの対象）
- 置き換える／置き換えられた ADR: なし

## 要求と決定
- プロダクトの特性と、満たす要求:
  - プロバイダーは 15 種あり（`apps/bot/src/config.ts`）、カタログのプリセットは 30 件、そのうち Anthropic は 4 件（`packages/shared/src/catalog.ts`）。既定は codex_plus / gpt-6-luna
  - Anthropic のプリセットは Premium 以上が設定する決まりで、従量課金（#35）。Free の利用者は既定を使っている
  - 要求は 3 つ。新しく非推奨のプリセットを選ぶ人を無くすこと。すでに選んでいる guild とユーザーは、設定を変えずに使い続けられること。非推奨のプロバイダーに送るリクエストが、ハーネスの作り直し（ADR-0009）の前後で変わらないこと
- 採用する構成・方式（「未定」と書いた点は、#67 で本人が決める。それまでは AI の提案）:
  - `anthropic` 以外の 14 種を非推奨にする。`claude_max` と `claude_kiro` も含む（確定）
    - （2026-10-12 追記）ADR-0011 がプロバイダー `anthropic_workspace` を足す（#76）。プロバイダーは 16 種になり、非推奨でないのは `anthropic` と `anthropic_workspace`。非推奨の 14 種と凍結の範囲は変わらない
  - 新しく選ぶ画面とコマンドから外し、使用中の人には非推奨の表示を出し、動作は今のハーネスのまま残す。削除はこの ADR では決めない（確定）
  - 既定（codex_plus / gpt-6-luna）と Free の利用者は、当面そのまま（確定）
  - 保存済みの選択は変換しない。「保存済みと同じ値は通し、新しく選ぶ非推奨だけ断る」判定（`newlyDeprecatedPresetIds`）を、API の PATCH と、bot の `/switch`・`set_bot_model` で使う。比べるのは欄ごと（メインのモデル、サブエージェントの共通モデル、役割ごとのモデル）。実行中のターンと子エージェントの可否（`canSelect`・`canUse`）は変えていない（AI の案のまま実装。本人未確認）
  - 非推奨の印は、カタログに関数として足す（`deprecatedProvider`・`deprecatedPreset`）。`published: false` は使わない。管理画面から戻せてしまい、偽にすると、非推奨の親を継ぐ子エージェントも起動できなくなるため（AI の案のまま実装。本人未確認）
  - 使用中の人への表示は、Web（現在の選択の「非推奨」の印、モデル一覧）、`/info` の 1 行、Discord での 1 回だけのお知らせ。お知らせの対象は、既定ではないモデルを自分で（サーバーまたは個人として）選んでいて、Anthropic のプリセットに切り替えられる利用者。出したことは `HIBANA_DATA_DIR/deprecation_notices.json` に残し、再起動後も繰り返さない（#67 の案 a。本人未確認）
  - API は `/api/catalog` の各プリセットに項目を足すだけにする。ルート・PATCH の項目・スナップショットの項目は増減しないので、契約は変わらない（ADR-0006）
  - 凍結の定義: 凍結するのは、プロンプト・ツール定義・正常時のリクエスト本文。非推奨のプロバイダー向けのリクエスト本文と、従来のハーネスの出力を、`harness-freeze.test.ts` で固定した。不具合修正（出力上限で切れた応答の再送、入力長の超過の判定、一時的な失敗の分類、Edit の置換文字列）は、従来のハーネスと `claude_max` にも効く。これらは応答の読み取りとツールの実行の側で、固定したリクエストは変わっていない（#67 の案 a。本人未確認）
- 比較した代替案と、採用しなかった理由（#67 の比較表。理由の整理は AI によるもので、持ち主の言葉での理由は聞いていない）:
  - 今回で削除する: 既定が Anthropic になり、Free の利用者の費用をどうするかの判断が先に要る。API の項目を削るには 2 回の配信が要る（ADR-0006）
  - 文書で宣言するだけ: 新しく選ぶ人が減らない

## 影響
- 得られる効果:
  - 新しい選択が Anthropic に寄る。既存の利用者と Free の利用者の動きは変わらない
  - 今のハーネスが残るので、新旧を同じビルドで比べられる（#69）
- 費用・運用の負荷・残る制約:
  - 非推奨のプロバイダーのコード、テスト、ダッシュボードの画面（Service Tier、ChatGPT アカウント）は残る
  - `claude_max` は `anthropic` と同じ Messages の経路を通る（`apps/bot/src/llm.ts` の `protocolFor`）。この経路の不具合修正を `claude_max` に当てるかどうかは未定（#67）
  - Free の利用者は、現在の選択と既定しか選べなくなる（隠す範囲を #67 の案 a にした場合）
- セキュリティ・障害時の挙動:
  - プロバイダーごとの認証情報の分離は変えない
  - 非推奨の表示は単独のメッセージにし、モデルに送る履歴には入れない（凍結したリクエストを変えないため）

## 実装と検証
- 適用した commit・構成図: この ADR を更新した PR
- 要求ごとの検証記録（手元の自動テスト）:
  - 分類、保存済みの選択が変わらないこと、同じ値と reset は通ること: `packages/shared/src/__tests__/deprecation.test.ts`
  - API が新しい非推奨の選択を 403 で断り、カタログに `deprecated` を出し、契約が変わらないこと: `apps/api/src/app.test.ts`、`contract.test.ts`
  - bot の `/switch`・`set_bot_model`・`/info`、非推奨の親を継ぐ子エージェントが従来どおり起動できること、お知らせが 1 回だけで再起動後も繰り返さないこと: `apps/bot/src/__tests__/deprecation.test.ts`
  - 画面: 非推奨が現在の選択のときだけ出ること、選べるモデルが無い利用者でも画面が壊れないこと: `apps/web/tests/design.spec.ts`（`bun run test:ui`）
  - 非推奨のプロバイダーに送るリクエストが変わらないこと: `apps/bot/src/__tests__/harness-freeze.test.ts`（スナップショットは変更なし）
- 実際の運用・CI/CD の実行記録: 未配信
- 検証していない範囲: 本番でプロバイダーごとに何 guild・何人が使っているか。実際の Discord での `/switch` の候補とお知らせの見え方。API 経由の bot では設定の反映に最大 30 秒かかるので、Web で非推奨から離れた直後に `/switch` で元の非推奨を指定すると通ることがある。従来のハーネスのツール説明（`set_bot_model`、子エージェントのモデルの一覧）には非推奨のプリセットが載ったままで、モデルが子エージェントに非推奨のプリセットを指定することは従来どおりできる

## 見直す条件
- この判断を見直す事象・数値:
  - 非推奨のプロバイダーを削除するとき、または既定を Anthropic に変えるとき（別の判断記録で決める）
  - 非推奨のプロバイダーの利用が続いていて、凍結したままでは困る不具合が出たとき
